## 审计发现

### #1 ⚠️ AI 练习题答案的可见性 — 需明确

**方案原文（T5 验收标准 #3）：**

> "AI 返回题目+参考答案，Core 输出给家长时显示题目，参考答案仅用于后续 `mkt check` 判题，Parent 可见。"

**问题：** 当前表述模糊——"Parent 可见"意味着 CLI 输出里会打印答案吗？如果是，Parent 看了答案再给孩子出题，孩子可能会无意中看到。

**建议：** `mkt review` 输出练习题时**不显示参考答案**。答案仅存储在 ReviewSession 文件中用于 `mkt check` 判题。Parent 判题时孩子已答完，此时答案可见无问题。

→ **修正后再确认。** 依据：A1（启发）要求"不直接给出完整解答"，虽然 Constitution 约束对象是学生，但系统设计应默认最小化答案暴露面。

---

### #2 ⚠️ `update_mistake_status` 的实现方式 — 需确认

**方案原文（T2）：**

> "update_mistake_status(mistake_id, new_status) → 改写文件内指定 Mistake 的状态字段"

**问题：** 这里说的"改写"是原地修改还是追加新行？Architecture §4.3 说的是"重写对应 .md 文件"——这可以理解为整个文件重写。CONTEXT Status 定义说"状态变更通过 ReviewSession 记录"。

**建议：** 明确实现策略：状态变更在原 Mistake 条目的状态行上直接修改（匹配 `**状态：** 未复习` → `**状态：** 已复习`）。ReviewSession 文件是变更的审计证据。两者配合满足 A8（可溯）+ A12（诚信）。不引入额外的状态日志行。

→ **方案接受此建议即可，代码层面无分歧。**

---

### #3 📝 待确认事项 #3 — 新 Topic 新增流程

**方案原文（待确认 #3）：**

> "PRD F1 和 ADR-003 提到'Parent 可新增，系统提示确认防重复'，但未规定新 topic 添加到 knowledge-points.yaml 的写入机制。"

**确认：** 这不是 Planner 的问题——Spec 在此处确实有留白。MVP 策略：

1. `mkt add` 发现未知 topic → 终端提示"未知知识点：{topic}。是否添加到 knowledge-points.yaml？(y/n)"
2. 用户确认 y → 追加到 YAML 文件对应学科/年级下
3. 用户 n → 拒绝录入
4. 此功能的代码放在 `service.py` 的 `add_mistake` 流程中，不单独抽函数

→ **Planner 按此实现即可，Spec 不留白。**

---

### #4 📝 新增命令：`mkt add --raw` — 批量导入

**语境：** Owner 计划用扫描仪→PaddleOCR→MD 文件的方式批量录入错题。当前 CLI 只支持逐字段输入。

**建议：** 在 Slice 1 中新增一个命令变体：

```
mkt add --raw 文件.md --student 开心 --grade 五年级上
```

流程：
1. 读取 MD 文件内容
2. 调用 `ai.py` 提取：subject、topic、question、wrong_answer、correct_answer、reason
3. 构造 Mistake → 走正常 `add_mistake` 流程
4. 逐条确认或全部确认

**工作量：** T4 `service.py` 加一个方法，复用已有 AI 调用。不推迟 Sprint。
