## 审计发现

### #1 ⚠️ 项目级 vs 模块级 Spec 未分层

**原文方案**：将 PRD、Architecture、ADR 全部放在 `错题整理系统/Spec/` 下。

**问题**：Constitution 是项目级的，但 PRD 可以是项目级或模块级。目前缺少项目级 PRD 预留位置。

**修正**：在 `LearningOS Spec/` 下预留 `prd.md` 位置（项目级 Learning OS 产品规范），本次 Sprint 不写。子模块级 Spec 保留在 `错题整理系统/Spec/` 内。

→ **已修正。**

### #2 ⚠️ 「垂直编程」未定义

**原文方案**：只建目录骨架，不跑通数据流。

**问题**：「垂直编程」的含义是**一条用户故事从上到下穿透所有层**（CLI → Service → Repository → Storage → CLI Output）。只建目录不跑数据流是水平搭建，不是垂直编程。

**修正**：Sprint 2 拆为两个 Phase：

| Phase | 内容 | 状态 |
|:---:|------|:---:|
| 2A | 规范体系建立（PRD + Architecture + ADR） | ✅ 完成 |
| 2B | 垂直切片：录入→存储→展示 的最小可运行代码 | ⏳ 待 CodeWhale |

→ **已通过，Phase 2B 定义清晰。**

### #3 📝 方案文件重复存储

**问题**：`v0.1_文件系统搭建_R1_方案_tbd_Kongzi.md` 同时存在于 `OS Audit/` 和 `错题整理系统/OS Audit/`。

**修正**：删除子模块内副本，保留 `OS Audit/` 下的唯一副本。

→ **已修正。**

## Phase 2B 移交清单（给 CodeWhale）

CodeWhale 拿到以下 Spec 后，实现第一条垂直切片：

### 必须实现的 CLI 命令

```
mkt add     --student <开心|开颜> --subject <科目> --topic <单元>
            --question <题目> --wrong <错误答案> --correct <正确答案>
            --reason <错误原因>

mkt list    --student <开心|开颜> [--subject <科目>] [--status <状态>]

mkt show    --id <uuid>
```

### 必须实现的层

| 文件 | 层 | 职责 |
|------|------|------|
| `src/core/models.py` | — | `MistakeRecord` dataclass |
| `src/core/repository.py` | Repository | `append()`, `read_all()`, `find_by_id()` |
| `src/core/service.py` | Service | `add_mistake()`, `list_mistakes()`, `get_mistake()` |
| `src/cli/main.py` | CLI | argparse 入口 |

### 实施约束（来自 Architecture §2.1）

- CLI 只能调用 Service
- Service 只能调用 Repository
- Repository 只能读写 `data/{student}/mistakes.jsonl`
- 禁止跨层调用

### 测试要求

- `tests/test_models.py` — 数据类构造测试
- `tests/test_repository.py` — 读写 JSONL 测试（使用 tmp_path fixture）
- `tests/test_service.py` — 业务逻辑测试（mock Repository）
