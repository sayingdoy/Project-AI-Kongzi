## 一、前置

Sprint 2B 交付了 Core Engine MVP（录入→查看→AI 复习→判题），Sprint 3 补完了状态机闭环（已掌握+二次错误回滚）。当前系统已具备完整的数据采集能力，但缺少**数据消费**层——家长登录系统后不知道"今天该干什么"。

Sprint 4 从"家长需要思考下一步"转为"系统主动告诉家长下一步"。

**全局 Roadmap 对应：**

| 版本 | 内容 | 当前状态 |
|:---:|------|:---:|
| v0.2 | 状态机闭环（已掌握 + 回滚） | ✅ Sprint 3 完成 |
| **v0.3** | **学习仪表盘 + 多学科** | **⏳ Sprint 4** |
| v0.4 | Web UI | 规划中 |

---

## 二、垂直切片设计

```
Slice 1（仪表盘核心）：   学习概览(mkt dashboard) → 知识点趋势(mkt trend)
Slice 2（智能推荐）：     推荐引擎(mkt recommend) → 复习排序算法
Slice 3（多学科扩展）：   knowledge-points 扩展 → subject 贯通测试
```

### 为什么这个顺序

仪表盘是"我有这么多数据了，告诉我看到了什么"——直接回答家长的核心焦虑。智能推荐更进一步，从描述现状到引导行动。多学科是纯扩展，与仪表盘无交叉依赖，可并行。

## 三、Task 分解

### T1 · 学习概览仪表盘（`mkt dashboard`）

**用户故事：** S4-1

**输入：** `mkt dashboard --student 开心`

**输出示例：**
```
开心 · 五年级 · 学习概览
──────────────────────────────
📖 活跃知识点：3 个（分数加法、小数乘法、分数减法）
✅ 已掌握：1 个（分数加法）
⏰ 待复测：1 个（小数乘法，已过复测期 2026-07-03）
📊 本周新增错题：2 条
📊 本周完成复习：1 次
⚡ 最薄弱知识点：分数减法（连续 2 次通分错误）
```

**实现位置：** `cli/main.py` 新增 `cmd_dashboard` + `service.py` 新增 `get_dashboard_data(student)`

**核心逻辑：**

| 数据项 | 来源 | 计算方式 |
|------|------|------|
| 活跃知识点数 | `list_mistakes` | 有未复习/已复习 Mistake 的 topic 去重计数 |
| 已掌握数 | `profile.knowledge_map` | mastered=True 的 topic 数 |
| 待复测数 | `profile.knowledge_map` | mastered=True + next_review <= today 的 topic 数 |
| 本周新增错题 | `list_mistakes` + created_at 过滤 | created_at >= 本周一的 Mistake 数 |
| 本周完成复习 | ReviewSession 文件 date 过滤 | date >= 本周一的 session 数 |
| 最薄弱知识点 | `list_mistakes` + `detect_trends` | 错题最多 / 趋势最频繁的 topic |

**验收标准：**
1. 输出包含 6 个字段：活跃知识点、已掌握、待复测、本周新增、本周复习、最薄弱
2. 数据为 0 时正确输出（不报错，不显示错误数据）
3. 不存在的学生给出明确错误

### T2 · 知识点趋势（`mkt trend`）

**用户故事：** S4-2

**输入：** `mkt trend --student 开心 --topic 分数加法`

**输出示例：**
```
分数加法 · 学习趋势
──────────────────────────────
📅 2026-06-01  录入错题：3/4+1/2=？(概念不清)
📅 2026-06-15  录入错题：1/3+1/2=？(概念不清)
📅 2026-06-20  🔄 复习（3/3 通过）→ 已复习
📅 2026-06-25  ✅ 掌握度验证（5/5 通过）→ 已掌握
📅 2026-06-28  ⚠️ 二次错误：1/4+1/2=？ → 回滚为未复习
📅 2026-06-29  🔄 复习（2/3 通过）→ 有错题转为新 Mistake

📊 汇总：共 4 条错题 | 掌握状态：未掌握 | 当前待复习：1 条
```

**实现位置：** `cli/main.py` 新增 `cmd_trend` + `service.py` 新增 `get_trend(student, topic)`

**核心逻辑：**
- 读取该 topic 下所有 Mistake（按 created_at 排序）
- 读取 ReviewSession 文件中的复习记录（找到该 topic 的记录）
- 读取 profile 中的回滚和掌握状态变更
- 合并为时间线输出

**验收标准：**
1. 时间线按日期排序，包含所有事件（录入、复习、已掌握、回滚）
2. 末尾汇总行
3. 空 topic 给出明确提示

### T3 · 智能推荐（`mkt recommend`）

**用户故事：** S4-3

**输入：** `mkt recommend --student 开心`

**输出示例：**
```
📋 今日复习推荐
──────────────────────────────
🥇 小数乘法（推荐指数：92%）
   理由：已过复测期 3 天 | 近期新增 1 条错题
   命令：mkt verify --student 开心 --topic 小数乘法

🥈 分数减法（推荐指数：75%）
   理由：当前 2 条错题未复习 | 通分错误连续出现
   命令：mkt review --student 开心 --topic 分数减法

🥉 简易方程（推荐指数：45%）
   理由：已掌握超 30 天，该复测了
   命令：mkt verify --student 开心 --topic 简易方程
```

**推荐算法（MVP 简化版）：**

| 因子 | 权重 | 说明 |
|------|:---:|------|
| 待复测天数 | 30% | next_review 超过今天的天数 |
| 未复习错题数 | 25% | status=未复习 的 Mistake 数 |
| 二次错误标记 | 20% | 最近有回滚事件 |
| 趋势严重度 | 15% | 学习趋势中 pattern 出现的频次 |
| 距上次复习天数 | 10% | 越久越优先 |

综合评分 = Σ(因子值 × 权重)，输出 Top-3。

**验收标准：**
1. 至少输出 1 条推荐（有任意数据时）
2. 每条推荐含 reason（为什么推荐它）和 command（具体 CLI 命令）
3. 无数据时输出友好提示

### T4 · 多学科扩展

**用户故事：** S4-4（英语）+ S4-5（语文）

**前置条件：** knowledge-points.yaml 中英语和语文已包含基础知识点条目。

**变更范围：**

| 文件 | 变更 |
|------|------|
| `shared/knowledge-points.yaml` | 英语/语文 各年级知识点条目（参考课标） |
| `core/service.py` | `add_mistake` / `list_mistakes` / `review` 的 subject 校验已支持英语/语文（VALID_SUBJECTS 已包含） |
| `cli/main.py` | `cmd_review` 的 `--subject` 默认值保持"数学"不变，但传入英语/语文时正常工作 |
| `core/ai.py` | Prompt 构造中的"小学数学分析"改为动态匹配 subject |

**不需更改的：** models.py 的 fields、repository.py 的路径逻辑、profile.py 的 knowledge_map——它们本就按 `subject` 维度隔离。

**验收标准（英语）：**
1. `mkt add --subject 英语 --topic 一般现在时 ...` → 文件写入 `users/{student}/data/错题整理/错题集/英语/...`
2. `mkt list --subject 英语` → 只返回英语错题
3. `mkt review --student 开心 --topic 一般现在时 --subject 英语` → AI 生成英语复习内容

**验收标准（语文）：**
1. 同上，subject=语文

## 六、风险点

| # | 风险 | 缓解 |
|:---:|------|------|
| R1 | **知识图谱时间线不完整** — ReviewSession 文件未记录所有事件 | `mkt trend` 从 Mistake 的 created_at + profile 状态变更推断，ReviewSession 作为辅助。不依赖 session 全记录 |
| R2 | **推荐算法权重不合理** — 固定权重可能不适应所有学生 | MVP 固定权重，留出 profile 中可配置权重字段的未来扩展点 |
| R3 | **英语/语文知识点不完整** — 缺乏课标参考 | MVP 先录入最常见的 10-20 个知识点，覆盖常用语法和阅读题型即可。后续逐步补充 |
| R4 | **AI 英语分析质量** — AI 可能不擅长分析英语错题 | Prompt 中显式说明 subject=英语，要求 AI 用中文分析英语语法错误（家长是中文用户） |

## 八、决策依据汇总

| 决策 | 选择 | 依据 |
|:---:|------|------|
| 仪表盘形式 | CLI 文本输出 | R2（简洁优先），不引入 Web |
| 趋势数据来源 | Mistake + profile + ReviewSession 三源合并 | A8（可溯），每条事件有证据 |
| 推荐算法 | MVP 固定权重公式 | R2，不引入 ML/配置 |
| 多学科路径 | 共享同一套代码 + 文件路径 | Architecture 本就按 subject 隔离 |
| AI Prompt 学科动态化 | 从 subject 参数注入 | A2（因材），不同学科不同分析方式 |
| 英语分析语言 | AI 用中文分析英语错误 | Parent 是中文用户（PRD §2） |

## 十、待确认

1. **英语知识点范围**：MVP 阶段英语知识点覆盖哪些内容？建议：一般现在时、现在进行时、一般过去时、一般将来时、第三人称单数、名词复数、形容词比较级——7 个常见小学语法点。语文暂放最低覆盖（拼音、笔顺、阅读理解）。
2. **推荐算法的可配置性**：当前 MVP 固定权重。若后期需要个性化，是通过 profile.yaml 新增字段（JSON 权重组）还是环境变量？建议暂不引入，Sprint 5 再说。
3. **仪表盘是否需要历史数据快照**：`mkt dashboard` 显示的是"当前"状态。若需要"上周 vs 这周"对比，需要存储仪表盘快照。建议 MVP 不做快照——数据全在当前文件中可计算。
